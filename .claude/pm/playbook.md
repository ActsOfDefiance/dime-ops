# PM Playbook

Learned decision patterns. Updated automatically when the PM is corrected. Uses "we" consensus language — never individual names.

## Priority Patterns
- Security issues are always P0-critical
- Issues with dependents (other issues blocked by this one) are P1-high
- We prefer tackling issues that unblock the most downstream work first
- We prefer resolving blocking decisions before starting dependent work, even if unblocked paths are available

## Triage Patterns
- Labels for type and domain are applied automatically without asking
- Priority is suggested with reasoning for anything that isn't security or dependency-driven

## Process Patterns
- Local markdown is for planning; GitHub Issues are canonical for active work
- Issues are promoted to GitHub when they have clear scope, acceptance criteria, and an epic
- We use "we" language in all process docs and playbook entries — this is a consensus-driven open source project
