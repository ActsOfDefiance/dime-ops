---
name: Collaboration style — discuss before deciding
description: When user asks to discuss something, have the actual conversation. Do not skip to conclusions.
type: feedback
---

When the user presents topics for discussion, discuss them. Ask questions, present options, wait for responses. Do NOT convert discussion topics directly into decisions or write them into docs as if they were settled.

**Why:** The user explicitly raised multi-repo structure and project management as discussion topics. Instead of talking through them, the assistant wrote them into a decisions doc as fait accompli. This was frustrating and disrespectful of the user's input.
**How to apply:** If the user says "let's discuss X" or "what are your thoughts on X" — respond with actual questions and reasoning. Only write things into specs or decisions docs after the user has agreed to them.
